# 动画素材渲染方案对比研究（Lottie / Rive / SVGA / PAG / VAP）

## 结论摘要

按**技术路线**分组比较，而不是五库平铺排名——它们解决的是四类不同问题：

```text
UI 微交互 / 可交互动效   → 矢量时间轴：Rive（新） / Lottie（AE 存量工作流）
直播礼物 / 贴图动效      → 贴图序列：SVGA（遗留生态） / VAP（高保真替代）
开屏 / 品牌大特效跨端一致 → 混合图层引擎：PAG
粒子光影等位图级特效     → Alpha 视频：VAP
```

选型原则：

- 先判**素材表达能力档位**（矢量 → 图层 → 贴图 → 视频），再在档位内选库；跨档位比较性能没有意义。
- 生产工具链决定迁移成本：Lottie 背靠 After Effects 存量资产，Rive 需要设计侧换编辑器，PAG 有 AE 插件直出，SVGA 依赖已萎缩的 Flash 系供给。
- 核心业务状态与动画解耦：动效素材方案只是表现层，任何档位都不承载数据流。

## 一句话定位

| 方案     | 本质                                        | 最适合                         | 最大短板                                 |
|--------|-------------------------------------------|-----------------------------|--------------------------------------|
| Lottie | AE 导出的 JSON 矢量时间轴，运行时 Canvas 软件绘制      | 已有 AE 工作流的 UI 图标 / 空状态动效    | 无交互状态机概念，复杂素材 JSON 体积与解析开销快速膨胀    |
| Rive   | 专有二进制 `.riv`，C++ 运行时，动画+状态机同文件         | 需要响应输入的交互动效、新一代矢量特效        | View 轨道官方标注 legacy、Compose 新轨道尚在过渡期 |
| SVGA   | 位图贴图槽 + 逐帧仿射变换时间轴（Flash 时代遗产格式）         | 直播礼物等「贴图换皮」型存量素材生态          | 拿不到图层数组，无属性级 API；供给与维护明显萎缩          |
| PAG    | 类 AE 二进制时间轴，矢量+位图+效果器混合图层引擎，C++ 跨端一致渲染 | 开屏 / 品牌大特效，要求多端逐帧一致         | 社区版不支持音视频内容；引擎与素材工具链绑定较深            |
| VAP    | MP4 分区存 Alpha 通道，MediaCodec 硬解 + OpenGL 合成 | 粒子、光影等矢量画不动的高保真特效与融合图文      | 素材即视频：体积大、改内容必须回炉导出，无图层级控制          |

## 核心机制

### 矢量时间轴：Lottie

Lottie（`lottie-android`）渲染 After Effects 通过 Bodymovin 导出的 JSON：形状、路径、关键帧与
插值全部以矢量描述，运行时用 Canvas 软件绘制，缩放无失真。

- 素材即数据：JSON 可读可改，程序侧也能动态改属性（Lottie Dynamic Properties）。
- 播放控制是纯时间轴语义：帧号 / 进度 / 速度 / 循环次数，没有「输入驱动的分支」概念。
- 大素材的代价在解析：JSON 文本体积随图层数膨胀，主线程反序列化对低端机不友好，需缓存。

本仓演示：`LottieActivity`（布局预览，`assets/lottie.json`）。

### 矢量时间轴：Rive

Rive（`rive-android`）用专有二进制 `.riv` 同时装载动画与**状态机**：状态机以布尔 / 数字 / 触发器
输入为条件，在动画状态间迁移，交互逻辑随素材一起由设计侧交付。

- 渲染为 C++ 运行时驱动，视图层是 TextureView 透明合成；视图构造与文件解码都依赖 native 库，
  使用前必须完成 `Rive.init`（11.x 起库清单移除了 androidx.startup 自动初始化项，须宿主手动初始化一次）。
- 与 Lottie 的代际差异在「素材内含逻辑」：切换等级、命中反馈这类分支不用 Kotlin 拼状态机。
- API 轨道分裂：官方主推的新 Compose API 尚在 beta→稳定过渡，View 轨道 `RiveAnimationView`
  KDoc 已标 legacy 但持续维护；本仓取 View 轨道与其余四库示例同构。

本仓演示：`RiveActivity`（`res/raw/anim_rive_skills.riv`：默认动画 + "Designer's Test"
状态机，`setNumberState` 切 Level 0/1/2）。

### 贴图序列：SVGA

SVGA（`SVGAPlayer-Android`）源自 Flash 礼物体系：素材是「位图图集 + 逐帧仿射变换」的
protobuf 二进制，播放即按帧把贴图槽绘制到画布。

- 动态能力只有内容替换：`SVGADynamicEntity` 按 `imageKey` 换图槽、替换文字与隐藏元素。
- 拿不到图层数组：`SVGAVideoEntity.spriteList` 为 internal，因此不存在 PAG 式的图层属性
  （矩阵 / alpha / 起始时间）与渲染树组合操作，这决定了它的 API 面天花板。
- 生态重心在直播礼物存量素材，格式与工具链多年基本冻结。

本仓演示：`SvgaActivity`（布局预览）、`SvgaImageActivity`（`setDynamicImage` 换图槽）。

### 混合图层引擎：PAG

PAG（`libpag`）是腾讯开源的通用跨平台动效引擎：AE 插件把源工程导出为二进制时间轴，
C++ 侧还原成 `PAGComposition / PAGImage / PAGText / PAGLayer` 图层树，各端逐帧一致渲染。

- 图层是公开 API：可对任意图层改矩阵、透明度、可见性、起始时间，也能组合多个素材
  拼渲染树（`PAGFile extends PAGComposition`）——这是 SVGA 没有的那条能力轴。
- 内容替换覆盖图片槽与文本槽，文本需取 `PAGText` 副本改字段后回灌。
- 能力边界：社区版不支持音视频内容（读 `numVideos()` 无碍，播放与导出音频属企业版
  `PAGMovie` 系），素材生产绑定 PAG 插件。

本仓演示：`PagPlayback / PagImage / PagText / PagLayer / PagComposition` 五页（`assets/pag/`）。

### Alpha 视频：VAP

VAP（腾讯开源版）把「带透明通道的视频」做成动效容器：MP4 画面分区存 RGB 与 Alpha，
`AnimView` 用 MediaCodec 硬解、OpenGL 逐帧合成透明画面。

- 表达能力档位最高：粒子、光斑、烟雾等逐像素特效无需引擎建模，效果上限即视频上限。
- 代价同样直接：素材是视频，体积大；改内容必须重新导出，程序侧只有「按 srcTag 供给融合
  图文」这一个注入点（`IFetchResource`）。
- 播放语义偏解码器而非时间轴：`setLoop` 是剩余次数倒计时且会被解码消耗回写，
  `stopPlay` 异步生效，切换素材须在 `onVideoComplete` 里接力起播。
- 官方已转向需 License 的 Vap Pro 商业 SDK，开源版（MIT）保持现状维护。

本仓演示：`VapActivity`（`assets/vap/`：纯播放 + 融合图文两素材）。

## 关键维度对比

| 维度           | Lottie           | Rive                       | SVGA                  | PAG                          | VAP                    |
|--------------|------------------|----------------------------|-----------------------|------------------------------|------------------------|
| 素材格式         | JSON（矢量描述）       | `.riv` 二进制（矢量+逻辑）        | protobuf（图集+帧变换）      | 二进制时间轴（矢量+位图+效果器）          | MP4（RGB/Alpha 分区视频）   |
| 生产工具         | AE + Bodymovin   | Rive Editor                | 已萎缩的 Flash 系导出链       | AE + PAG 插件                  | 视频/特效软件导出             |
| 渲染模型         | Canvas 软件绘制      | C++ 运行时 + TextureView      | Canvas 逐帧位图绘制         | C++ 引擎跨端一致                  | MediaCodec 硬解 + GL 合成  |
| 交互能力         | 无内建状态机          | 状态机+输入为素材一级公民            | 无                    | 无状态机，靠外部驱动时间轴与图层属性         | 无，仅有资源回调/点击透传        |
| 动态替换         | 动态属性 API        | 文本/图片运行时绑定 + ViewModel   | `imageKey` 换图槽 / 换文字  | 图片槽 / 文本槽回灌                 | `IFetchResource` 按 srcTag |
| 图层控制         | 隐式（按 name 找层）   | 状态机与 artboard 层级          | 无（spriteList internal） | 完整 PAGLayer API               | 无                      |
| 包体/引擎成本      | Java 库，轻         | 含 native `.so`             | Java 库，轻              | native 引擎体积大                 | native + 解码器，素材本身最大    |
| 生命周期负担       | View 内建         | 视图绑 LifecycleOwner，释放引用计数 | 手动 pause/resume       | 手动 play/stop，帧回调异步           | 手动 start/stop，停止异步生效   |
| 跨端一致性        | 各端渲染器近似        | C++ 同源，跨端一致               | 各端播放器各自实现            | 强项（设计目标即跨端一致）                | 取决于解码器实现               |
| 生态趋势         | 存量大、创新放缓        | 官方主推方向                    | 遗留维持                 | 腾讯系活跃                       | 开源版冻结，商业版接棒            |

## 常见坑位

### Lottie

- 大 JSON 的解析在装载侧发生，低端机首帧延迟明显；重复素材务必启用缓存或预解析。
- 把交互逻辑写进 Kotlin「监听点击 → 切帧段」是反模式——这正是 Rive 状态机要解决的问题。

### Rive

- 忘记或排晚 `Rive.init`：`RiveAnimationView` 构造时即实例化 native FileAssetLoader，
  把 init 排在 inflate 之后会直接崩在视图构造（UnsatisfiedLinkError），必须在创建视图前完成。
- 输入名与状态机名是设计侧命名，代码字符串必须与素材一致；状态机未在播放时改输入，
  画面不会有任何反馈，容易误判 API 失效。
- API 轨道换代期：View 轨道 KDoc 标 deprecated（WARNING，持续维护），新 Compose API
  为 beta；选型前确认目标宿主是 View 还是 Compose。

### SVGA

- 想要「改图层属性」类的操作请先放弃：API 面只有内容替换，需要图层级控制即触发选型
  问题（迁 PAG），不要在播放器子类里翻 internal 结构硬啃。
- 换图槽要求新图按槽尺寸自行裁切对齐，素材侧 imageKey 命名不可从外部枚举获知。

### PAG

- `replaceText` 需要取 `PAGText` 副本、改字段、再回灌，直接改取回的引用无效。
- 图层附加矩阵是与动画矩阵**拼接**而非替换，且锚点在合成坐标系，不是元素自身中心。
- 音视频内容在社区版走不通，评估素材含音轨时先确认授权档位。

### VAP

- `setLoop` 次数会被解码消耗并回写，每次起播前必须重设，否则静默退回单次。
- `stopPlay` 只置标记，切换素材的正确姿势是在 `onVideoComplete` 里接力起播。
- `IFetchResource` 无论成败都必须回调 result，漏一次播放线程就无限等待。
- 融合素材的 `vapc` 配置较大时，assets 流式读取可能截断，先拷到缓存文件再播放。

## 场景选型

### UI 微交互 / 可交互动效（loading、按钮反馈、空状态、引导）

矢量档位。存量 AE 资产继续 Lottie；新起且需要「点击/状态迁移」的用 Rive，把交互分支
放进素材而不是散在页面代码里。二者同路线，迁移方向是 Lottie → Rive，不是并存扩张。

### 直播礼物 / 打赏贴图

贴图档位。新素材供给优先 VAP（保真、制作即录屏）；SVGA 只在承接存量素材生态时保留，
新增特效不建议再入 SVGA 工具链。礼物文案/头像注入两者都能做（SVGA 换图槽，VAP 融合图文）。

### 开屏 / 品牌大特效 / 多端逐帧一致

图层引擎档位。PAG 是该档位唯一开源成熟选项；同素材双端（Android/iOS/Flutter）表现
一致是其核心卖点。含音轨需求先过企业版评估。

### 粒子、光影、烟雾级特效

视频档位，即 VAP。此档若 PAG 效果器也能覆盖（社区版支持大部分 AE 效果器），
优先 PAG——矢量/图层可替换、可复用；VAP 留给「只有视频能画出来」的素材。

### 相邻域边界（不在本矩阵内）

- **GIF / APNG / WebP 动图**：属图片解码域，归 `module_image_loader` 对照，不承担动效逻辑。
- **Spine / DragonBones / Live2D 骨骼动画**：角色向独立路线，与 UI 动效素材不重叠。
- **AnimatedVectorDrawable / 属性动画**：系统原生路线，见 `activity/system/` 与原生动画页。

## 最终建议

- 五库不是同一问题的五个答案，而是**四个档位的代表**：选型先定档位（要交互→矢量，
  要贴图→SVGA/VAP，要跨端大特效→PAG，要位图保真→VAP），再在档位内比较。
- 唯一真正互相替代的一对是 Lottie / Rive（矢量档内代际）与 SVGA / VAP（贴图档内新旧）；
  PAG 与 VAP 在「特效」场景的竞争以**素材是否含可替换槽位**为判据。
- 存量迁移优先级：仅当触碰对应页面时顺带，禁止为「现代化」批量替换教材矩阵成员。

## 双端运行时矩阵（Android / Flutter）

五档素材在 Flutter 侧都有对应运行时轨道，示例见 `flutter/flutter_demo/lib/demos/animation/`
（SVG 为 Flutter 专有补充，Android 侧走系统 Vector）。

| 方案 | Android 依赖 | Flutter 依赖 | 素材 | 端侧 API 差异 |
|---|---|---|---|---|
| Lottie | `com.airbnb.android:lottie` 6.6.7 | `lottie` 3.3.2（Dart 重实现） | 同一份 JSON | 两端都是纯时间轴语义，Flutter 侧无动态属性入口 |
| Rive | `app.rive:rive-android` 11.16.3（View 轨道） | `rive` 0.14.11（`rive_native` C++） | 同一份 `skills.riv` | 新运行时把状态机输入 API（`number`/`boolean`/`trigger`）标注废弃并指向 Data Binding，程序化写 Level 仅 View 轨道可用，Flutter 侧由素材内按钮的指针监听驱动；另有 `Factory.rive` / `Factory.flutter` 双渲染轨道与构建期下载 native 库 |
| SVGA | `com.github.yyued:SVGAPlayer-Android` 2.6.1 | `flutter_svga` 0.0.13 | 各端一份素材 | 两端一致只有内容替换，无图层属性轴 |
| PAG | `com.tencent.tav:libpag` 4.5.12 | `pag_flutter` 0.0.1 | 各端一份素材 | 同一 C++ 引擎，跨端逐帧一致是其设计目标；Flutter 侧示例仅覆盖播放 |
| VAP | `io.github.tencent:vap` 2.0.28 | `flutter_vap_plus` 1.2.10（PlatformView 包 `AnimView`） | 同一份 `demo.mp4` / `vapx.mp4` / 融合头像 | Flutter 插件 Android 侧同坐标 `io.github.tencent:vap:2.0.28`，解码器即同一份；控制面收窄：无 `setLoop`、无融合资源点击监听，融合素材与头像须先落盘（`playAsset` 走 `flutter_assets/` 流式读取 + `BitmapFactory.decodeFile` 只认文件路径） |

矩阵读法：素材档位是跨端不变量，运行时 API 面才是端侧变量。Rive 与 VAP 两条轴的差异
不是「Flutter 少实现」，而是各自的代际/封装取舍——Rive 新运行时用 Data Binding 取代命名输入，
VAP 无官方 Dart 运行时、只能靠原生播放器桥接。
